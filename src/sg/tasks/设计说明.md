# 队列调度（Queue Task）设计说明

## 1. 背景

项目里需要"并发跑一批任务，边跑边补，直到跑够为止"的模式。典型场景：

- 派部队去打巨兽、采集、做活动
- 日常开免费宝箱、领取任务奖励
- 后续可能还有更多类型

这些场景的**执行形态**相同（都是队列 + 自动补任务），**业务内容**不同。

如果为每一种业务都复制一份完整的调度代码，会产生：

- 大量重复（tick 循环、paused / exit 处理、info 刷新……）
- 加一种业务就要改一堆地方
- GUI 配置每加一种都要手写一遍

因此引入统一的分层设计。

---

## 2. 术语约定（非常重要）

本项目把"队列"和"业务"严格区分：

| 术语 | 归属 | 含义 | 出现在哪 |
|---|---|---|---|
| **Queue（队列）** | 开发 | 数据结构 / 调度模式 | `scheduler/`、`tasks/queue/`、内部变量 |
| **Task** | 开发 | 单个可执行单元 | 全项目通用 |
| **Troop（部队）** | 游戏 | **战斗 / 派出类**业务的术语 | 仅 `HuntMonsterTroop` 等战斗类 |
| **Daily（日常）** | 游戏 | 日常类业务 | `DailyChest`、`ClaimReward` |
| **Activity（活动）** | 游戏 | 活动类业务 | `ActivityRunner` |

**三条铁律**：

1. 类名里出现 **Queue** → 属于开发层，禁止 import 任何业务包
2. 类名里出现 **业务词**（Troop / Daily / Activity / …）→ 属于业务层
3. **UI / log 里不出现 Queue 字样**，玩家视角只看到游戏概念

## 3. 分层结构

```
┌─────────────────────────────────────────────────────────┐
│  scheduler/task_queue.py                                │
│  TaskQueue / TaskFactory                                │
│  纯开发基础设施，不依赖 SG                              │
└─────────────────────────────────────────────────────────┘
                    ▲
                    │ 使用
┌─────────────────────────────────────────────────────────┐
│  sg/tasks/queue/QueueTaskBase.py                        │
│  把 TaskQueue "适配"成 SGBaseTask                       │
│  负责：生命周期、tick 循环、paused / exit、info         │
│  与业务无关                                             │
└─────────────────────────────────────────────────────────┘
                    ▲
                    │ 继承
┌─────────────────────────────────────────────────────────┐
│  sg/tasks/queue/GenericQueueTask.py                     │
│  通用注册表 + GUI 自动展开                              │
│  通过 register_task_type(...) 支持任意业务类型          │
│  与业务无关                                             │
└─────────────────────────────────────────────────────────┘
                    ▲
                    │ 继承 + 注册
┌─────────────────────────────────────────────────────────┐
│  sg/tasks/world/HuntMonsterTroop.py                     │
│  sg/tasks/daily/DailyChest.py                           │
│  sg/tasks/activity/ActivityRunner.py                    │
│  ……                                                     │
│  业务层，各用各的术语，只负责"注册"                      │
└─────────────────────────────────────────────────────────┘
```

## 4. 各层职责

### 4.1 `TaskQueue` / `TaskFactory`（scheduler）

纯数据结构 + 补任务逻辑。它只认识"工厂"和"任务"，完全不知道 SG 的存在。

- `TaskQueue.add_factory(f)`：注册一个工厂
- `TaskQueue.tick()`：每次调用时检查并补任务
- `TaskQueue.all_done()`：是否全部完成
- `TaskQueue.get_snapshot()`：获取进度快照

### 4.2 `QueueTaskBase`（tasks/queue）

把 TaskQueue 塞进 SGBaseTask 的生命周期里。**唯一职责**：让"跑一个队列"这件事变成"跑一个普通任务"。

- 提供统一的 `run()`，处理 tick / paused / exit
- 提供统一的 `_update_info()`
- 定义抽象接口 `_build_factories()`，让子类告诉它跑什么

### 4.3 `GenericQueueTask`（tasks/queue）

提供**注册表机制**，让一个队列同时承载多种业务类型。

- `TASK_REGISTRY`：全局注册表
- `register_task_type(...)`：注册入口
- `_build_config()`：根据注册表自动展开 GUI 配置
- `_build_factories()`：只把启用的类型转成 TaskFactory

### 4.4 业务文件（tasks/world、tasks/daily、tasks/activity）

只做两件事：

1. 调用 `register_task_type(...)` 描述自己的业务参数
2. 提供一个薄壳类（继承 GenericQueueTask）用于在 GUI 任务列表里单独展示

## 5. 数据流

```
用户启动任务
     │
     ▼
QueueTaskBase.run()
     │
     ├─ 构造 TaskQueue
     │
     ├─ 调用子类 _build_factories()
     │       │
     │       ▼
     │  GenericQueueTask._build_factories()
     │       │
     │       └─ 遍历 TASK_REGISTRY
     │           ├─ 跳过 Enabled=False 的类型
     │           └─ 把启用的类型转成 TaskFactory
     │
     ├─ while not all_done():
     │     queue.tick()          ← 队列按 Max Active 自动补任务
     │     _update_info()        ← 刷新 UI
     │     sleep(tick_interval)
     │
     └─ queue.stop()
```

## 6. GUI 自动展开

每种注册项会自动展开为以下几项：

```
{key}: Enabled      —— 是否启用（默认 False）
{key}: Count        —— 执行次数（0 = 无限）
{key}: Max Active   —— 并发上限
{key}: {extra_key}  —— 注册时声明的业务参数
```

例如注册：

```python
GenericQueueTask.register_task_type(
    key="Hunt Monster Troop",
    extra_config={
        "Monster Level": {"default": 1, "type": {"type": "drop_down", "options": [...]}},
        "Auto Recall":   {"default": False},
    },
)
```

GUI 上自动出现：

```
Hunt Monster Troop: Enabled      □
Hunt Monster Troop: Count        5
Hunt Monster Troop: Max Active   3
Hunt Monster Troop: Monster Level [1 ▾]
Hunt Monster Troop: Auto Recall  □
```

## 7. 如何新增一种业务

以"新增副本扫荡"为例：

### Step 1：写一个业务任务类

```python
# src/sg/tasks/world/DungeonSweepTask.py
class DungeonSweepTask(SGBaseTask):
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.name = "Dungeon Sweep"
        self.default_config.update({"Dungeon ID": 1})
        ...

    def run(self):
        dungeon_id = int(self.config.get("Dungeon ID", 1))
        ...
```

### Step 2：写一个注册文件

```python
# src/sg/tasks/world/DungeonSweep.py
from src.sg.tasks.queue.GenericQueueTask import GenericQueueTask
from src.sg.tasks.world.DungeonSweepTask import DungeonSweepTask

GenericQueueTask.register_task_type(
    key="Dungeon Sweep",
    task_class=DungeonSweepTask,
    name_prefix="Dungeon Sweep",
    default_count=3,
    default_max_active=1,
    default_kwargs={},
    description="副本扫荡。Sweep dungeon.",
    extra_config={
        "Dungeon ID": {"default": 1, "desc": "副本 ID"},
    },
)
```

### Step 3：在入口 import 一次

```python
# src/sg/tasks/__init__.py
from .world import DungeonSweep   # noqa: F401
```

**完成。** GUI 上会自动多出 `Dungeon Sweep: *` 的配置项，无需改任何队列代码。

## 8. 禁止事项

| 禁止 | 原因 |
|---|---|
| 在 `queue/` 包里 import 任何业务包 | 破坏"与业务无关"的约定，形成循环依赖 |
| 在 `queue/` 包里的类名 / 注释出现"部队""巨兽""宝箱" | 这些是业务术语，应留在业务包里 |
| 在业务文件里再写一遍 tick / paused / exit 处理 | 应该在 QueueTaskBase 里统一 |
| 给每种业务复制一份 `GenericQueueTask` | 违背本设计的初衷 |
| 在 UI 文案 / log 里出现 "Queue" | 玩家视角只应看到游戏术语 |

## 9. 常见问题

**Q：为什么不用多继承 / Mixin？**

A：注册表机制比 Mixin 更灵活——Mixin 需要在编译期确定组合，
注册表在运行期就能拼装，且天然支持 GUI 自动展开。

**Q：为什么 `register_task_type` 是类方法而不是实例方法？**

A：因为注册发生在**模块 import 阶段**，此时还没有实例。
类方法让注册可以脱离实例运行。

**Q：如果两个业务模块注册了同一个 key 怎么办？**

A：后注册的会覆盖先注册的。建议 key 保持全局唯一，
可以在 CI 里加一条检查规则。

**Q：`self._factories.clear()` 是必要的吗？**

A：是。如果同一个任务实例被 run 两次（比如测试里），
保留旧工厂会导致重复提交。clear 保证每次 run 都是干净的。

**Q：`GenericQueueTask` 与"部队"真的无关吗？**

A：是的。可以用它调度任何东西——
开宝箱、领奖励、跑活动、扫副本……
"部队"只是**其中一类业务**的术语，
不构成对队列的任何约束。
