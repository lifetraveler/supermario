# 2 奔奔王国自动化架构设计 - Scene Architecture

# 1. 目标

建立统一的游戏场景识别系统。

Scene 系统只负责：

1. 判断当前所在场景
2. 判断当前场景状态
3. 提供场景元素
4. 提供场景上下文

Scene 不负责：

- 业务任务
- 复杂流程
- 游戏策略
- 自动循环

---

# 2. 四层架构

```text
Task
  ↓
Navigator
  ↓
Scene
  ↓
Element
  ↓
Action
  ↓
OK-Script
```

---

# 3. Scene

Scene 表示：

> 当前游戏处于哪个页面/场景。

```python
class Scene:
    type
    state
    confidence
    elements
```

例如：

```python
Scene(
    type=SceneType.CITY,
    state=SceneState.NORMAL,
    confidence=0.97
)
```

---

# 4. SceneType

```python
class SceneType:

    UNKNOWN = "unknown"

    LOGIN = "login"

    CITY = "city"

    WORLD_MAP = "world_map"

    TOWER_DEFENSE = "tower_defense"

    MARCH = "march"

    HERO = "hero"

    TROOP = "troop"

    TECH = "tech"

    ALLIANCE = "alliance"

    QUEST = "quest"

    ACTIVITY = "activity"

    MAIL = "mail"

    SHOP = "shop"

    REWARD = "reward"
```

---

# 5. SceneState

SceneType 解决：

```text
我在哪里？
```

SceneState 解决：

```text
我现在正在做什么？
```

例如：

```python
class SceneState:

    NORMAL = "normal"

    LOADING = "loading"

    PREPARE = "prepare"

    FIGHTING = "fighting"

    WIN = "win"

    LOSE = "lose"

    BUILDING = "building"

    UPGRADING = "upgrading"

    SEARCHING = "searching"

    MARCHING = "marching"

    GATHERING = "gathering"

    REWARD = "reward"

    ERROR = "error"
```

---

# 5. Element

Element 表示：

> 当前场景中的具体 UI / 游戏对象。

例如：

```python
Element(
    name="world_button",
    bounds=(100, 900, 180, 980),
    confidence=0.98
)
```

---

# 6. Element 不绑定 Task

错误：

```python
element.click_and_start_gather()
```

正确：

```python
element.click()
```

Element 只提供：

```text
位置
大小
置信度
类型
```

---

# 7. Action

Action 是最基础的操作。

```text
Click
Swipe
LongPress
Wait
Input
OCR
TemplateMatch
```

例如：

```python
click(element)

swipe(start, end)

wait(2)

ocr(region)
```

---

# 8. Navigator

Navigator 负责场景之间的移动。

例如：

```python
navigator.go_to(SceneType.CITY)

navigator.go_to(SceneType.WORLD_MAP)

navigator.go_to(SceneType.HERO)
```

Navigator 不负责：

```text
升级英雄
攻击野怪
采集资源
```

它只负责：

```text
怎么到这个页面
```

---

# 9. Task

Task 是业务流程。

例如：

```python
class GatherResourceTask(SGBaseTask):

    def run(self):

        navigator.go_to(SceneType.WORLD_MAP)

        target = self.find_resource()

        self.select_target(target)

        self.start_march()

        self.wait_result()
```

---

# 10. SceneDetector

SceneDetector 是核心识别模块。

```python
class SceneDetector:

    def detect(self, image) -> Scene:
        ...
```

推荐使用多特征判断，而不是单一图片。

---

# 11. Scene 判断

推荐：

```text
模板
+
OCR
+
固定 UI
+
场景特征
+
状态特征
```

例如 WORLD_MAP：

```text
世界地图按钮/地图 UI
+
地图地形
+
资源点
+
玩家城堡
```

CITY：

```text
资源栏
+
建筑区域
+
城镇中心
+
居民/建筑 UI
```

TOWER_DEFENSE：

```text
敌人
+
防御塔
+
波次
+
战斗 UI
```

---

# 12. Confidence

SceneDetector 必须返回 confidence。

```python
Scene(
    type=SceneType.CITY,
    confidence=0.96
)
```

建议：

```text
>= 0.90
    直接使用

0.70 ~ 0.90
    二次确认

< 0.70
    UNKNOWN
```

---

# 13. UNKNOWN

UNKNOWN 是非常重要的场景。

任何无法确定的情况：

```python
SceneType.UNKNOWN
```

不能强行判断成 CITY。

---

# 14. Popup 优先级

识别顺序：

```text
1. ERROR
2. REWARD
3. CONFIRM_DIALOG
4. BATTLE
5. MARCH
6. PAGE
7. CITY / WORLD_MAP
```

原因：

Popup 会覆盖底层页面。

---

# 16. Scene Detector 推荐流程

```text
截图
 ↓
检测全局 Popup
 ↓
检测 Loading
 ↓
检测 Battle
 ↓
检测 March
 ↓
检测页面
 ↓
计算 Confidence
 ↓
返回 Scene
```

---

# 17. Task 调用 Scene

推荐：

```python
scene = self.detect_scene()

if not scene.is(SceneType.WORLD_MAP):
    self.navigator.go_to(SceneType.WORLD_MAP)
```

而不是：

```python
if screenshot_contains_xxx():
    click(...)
```

---

# 18. Scene Cache

短时间内不要重复识别。

```python
scene = detector.detect()

cache(scene)

# 400ms ~ 1s 内优先使用缓存
```

但发生以下事件后必须重新检测：

```text
点击
滑动
页面跳转
弹窗出现
战斗状态改变
```

---

# 19. Task 生命周期

```text
INIT
 ↓
CHECK
 ↓
NAVIGATE
 ↓
EXECUTE
 ↓
VERIFY
 ↓
SUCCESS
```

失败：

```text
EXECUTE
 ↓
VERIFY
 ↓
FAILED
 ↓
RETRY / RECOVER
```

---

# 20. Recovery

所有 Task 都应该支持：

```python
recover()
```

例如：

```text
发现弹窗
→ 关闭

发现奖励
→ 领取

发现错误
→ 重连

发现未知页面
→ 返回主城

Scene 不匹配
→ Navigator 修正
```

# 24. 设计原则

## 原则 1

Scene ≠ Task

## 原则 2

Element ≠ Action

## 原则 3

Navigator ≠ Task

## 原则 4

UNKNOWN 永远是合法结果

## 原则 5

任何自动化操作之后都应该 Verify

## 原则 6

尽量通过场景状态驱动任务，而不是通过固定坐标驱动任务

## 原则 7

资源图片、Scene 逻辑、Task 逻辑分离



## 有一点我特别建议你注意

**不要现在就把所有游戏功能都实现。**

目前公开版本已经在不断增加玩法，例如 1.7.6 已经包含黄金深度探秘、神剑争夺、决战王城、宠物、绿洲岛等内容。([App Store][2])

所以 `scene.py` 最好做成**稳定的底层基础设施**，而不是把现在所有玩法硬编码进去。

你现在真正应该优先完成的是：

```text
截图
 ↓
SceneDetector
 ↓
CITY / WORLD_MAP / BATTLE / MARCH
 ↓
识别关键 Element
 ↓
Navigator
 ↓
再开始写 Task
```

尤其是 **`CITY` 和 `WORLD_MAP`**，这两个一旦识别稳定，后面的采集、升级、任务、英雄、联盟等自动化都会容易很多。
