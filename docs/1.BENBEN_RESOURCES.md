# 1 奔奔王国 - 场景与任务资源拆解

> 用于 OK-Script 自动化项目的场景识别、UI 元素识别、任务设计和后续扩展。
>
> 核心设计：
>
> - Scene：当前玩家处于什么场景
> - State：当前场景处于什么状态
> - Element：场景中有哪些可识别元素
> - Action：可以执行什么操作
> - Task：由多个 Action 组成的完整自动化任务

---

# 6. 设计原则

## Scene 不负责执行任务

错误：

```python
Scene.detect()
Scene.upgrade_building()
Scene.attack_monster()
```

正确：

```python
scene = detector.detect()

if scene.is_city():
    task.run()
```

---

## Task 不负责识别整个游戏

Task 只负责业务流程：

```text
Task
 ↓
Scene
 ↓
Action
 ↓
UI Element
 ↓
Click / Swipe / OCR
```

---

## Scene 负责回答

```text
我现在在哪里？
```

## Element 负责回答

```text
这个东西在哪里？
```

## Action 负责回答

```text
怎么操作？
```

## Task 负责回答

```text
我要完成什么目标？
```

# 8. Scene API 建议

```python
scene = Scene(
    type=SceneType.CITY,
    state=SceneState.NORMAL,
    confidence=0.96,
)

scene.is_city()

scene.has("town_center")

scene.find("quest_button")

scene.require("world_button")
```

---

# 9. Task API 建议

```python
class GatherResourceTask(SGBaseTask):

    def run(self):

        self.scene.require(SceneType.WORLD_MAP)

        target = self.find_resource()

        self.select_target(target)

        self.march()

        self.wait_for_result()
```

---

## 9.1 导航应该独立

不要在 Task 里大量写：

```python
click(...)
sleep(...)
click(...)
sleep(...)
```

应该提供：

```python
navigator.go_to(SceneType.CITY)
navigator.go_to(SceneType.WORLD_MAP)
navigator.go_to(SceneType.HERO)
navigator.go_to(SceneType.TECH)
```

这样所有 Task 都可以复用。
